<a name="はじめに"></a>

## はじめに

シーディングを使用するとマイグレーション済みのデータベーステーブルに初期データやダミーデータを投入でき新しい環境のセットアップを即座に完了できます。dframeworkはこれらのシーディング操作を定義および実行するためのシンプルな仕組みを提供します。

<a name="シーダーの記述"></a>

## シーダーの記述

シーダーファイルは`database/seeders/`ディレクトリに配置しテーブルへのデータ投入を担当します。マイグレーションと同様にシーダーファイルは非同期の`run`関数をエクスポートする必要があります。フレームワークは流暢な`table`クエリビルダーを含むコンテキストオブジェクトを注入し挿入操作への直接アクセスを提供します。

これらのコンテキストプロパティは実行中にグローバルでも利用可能です。

```javascript
export async function run({ table }) {
  await table('users').insert([
    {
      name: 'admin',
      email: 'admin@example.com',
      password: 'password'
    }
  ]);
}
```

<a name="シーダーの実行"></a>

## シーダーの実行

利用可能なすべてのシーダーを順番に実行するにはseedコマンドを実行します:

```bash
dstrn seed
```

特定のシーダーを個別に実行するにはシーダー名を引数として渡します:

```bash
dstrn seed UserSeeder
dstrn seed 001_UserSeeder
```

本番環境（`APP_ENV=production`）で実行する場合seedコマンドは誤ったデータ変更を防ぐために確認を求めます。自動プロビジョニングパイプラインでは`--force`フラグを使用します:

```bash
dstrn seed --force
```

<a name="自動安全性チェック"></a>

## 自動安全性チェック

シーダーランナーは本番環境での安全性を考慮して設計されています。

> [!NOTE]
> シーダー内でinsert文を実行する前にフレームワークは対象テーブルのレコード数をカウントします。レコードが存在する場合ランナーはそのシーダーのトランザクションをロールバックしシーダーファイル全体をスキップします。これにより主キーの衝突や重複行を発生させることなくシーダースイートを繰り返し安全に実行できます。
