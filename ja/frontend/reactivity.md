<a name="はじめに"></a>

## はじめに

dframeworkはソケットレイヤーを介してユーザーインターフェースとサーバー状態の同期を維持する2つの相補的なリアクティビティシステムを提供します。クライアント側のレンダリングフレームワークは関与しません。サーバーがHTMLをレンダリングし、フレームワークがそれを適切なDOMターゲットに局所的かつ的確に配信します。

<a name="システムの選択"></a>

## システムの選択

| 機能 | d-wire | d-live |
| --------- | ------------------------------- | ------------------------------------- |
| トリガー | 明示的なユーザー操作 | データベース書き込み |
| 最適な用途 | カウンター、検索、モーダル、フォーム | フィード、ダッシュボード、ライブリスト |
| 必要要件 | 名前付きソケットハンドラー | d-live属性（ハンドラー不要） |
| レンダリング | ハンドラーがrenderを呼び出し | フレームワークが自動再取得 |

意図的な操作から特定の結果をユーザーが期待する場合はd-wireを使用します。原因にかかわらずデータと領域の同期を維持する必要がある場合はd-liveを使用します。

<a name="d-wireイベント駆動リアクティビティ"></a>

## d-wireイベント駆動リアクティビティ

任意のHTML要素に`d-wire`を付与します。トリガーされると要素はソケット経由で名前付きイベントをソケットハンドラーに送信します。ハンドラーがパーシャルをレンダリングし、フレームワークが対象コンテナーをその結果で置き換えます。

```html
<button d-wire="counter:increment" d-target="#counter">+1</button>
```

<a name="データの受け渡し"></a>

### データの受け渡し

イベントとともにペイロードを送信するには`d-wire-data`を使用します。カンマ区切りのキーバリューペアまたは生のJSONを受け付けます。

```html
<button
  d-wire="post:like"
  d-wire-data="id:{{ post.id }}, type:'post'"
  d-target="#likes-{{ post.id }}">
  like
</button>

<button
  d-wire="user:update"
  d-wire-data='{"id": {{ user.id }}, "status": "active"}'
  d-target="#user-status">
  activate
</button>
```

ペイロードは存在するフォームデータとマージされハンドラー内でリクエストボディとしてアクセスできます。

<a name="バックエンドハンドラー"></a>

### バックエンドハンドラー

`d-wire`ハンドラーはrenderまたはjsonを呼び出す必要があります。レンダリングされたHTMLがクライアント上の対象要素を置き換えます。フレームワークはレンダリング結果をハッシュ化し、コンテンツに変更がない場合は更新を抑制して冗長なDOM操作を防ぎます。

> [!IMPORTANT]
> 任意のDOM注入を防ぐため、パーシャルをレンダリングするソケットルートは`.targets(['#target-id'])`をチェーンして許可されるクライアントターゲットを明示的に制限する必要があります。

```javascript
Socket.on('counter:increment', async (req) => {
  const count = await Counter.increment(req.body.id);
  return render('partials.counter', { count });
}).targets(['#counter']);

Socket.on('user:search', async (req) => {
  const users = await User.where('name', 'LIKE', `%${req.body.q}%`).limit(10).get();
  return render('partials.user-list', { users });
}).targets(['#user-list']);
```

<a name="トリガータイプ"></a>

### トリガータイプ

`d-wire`は各要素タイプに応じた自然なイベントにバインドされます。

| 要素 | デフォルトトリガー |
| --------------------- | --------------- |
| `<button>`, `<a>` | `click` |
| `<form>` | `submit` |
| `<input>`, `<select>` | `change` |

`d-trigger`で上書きできます。

```html
<input d-wire="user:search" d-target="#results" d-trigger="keyup" placeholder="search users">
```

特別なトリガー値も利用可能です。

| 値 | 挙動 |
| ----------- | --------------------------------------------------------- |
| `load` | 要素がマウントされた直後に一度だけ発火 |
| `poll-{ms}` | nミリ秒ごとに継続的に発火（例: `poll-5000`） |

<a name="プログラムによるディスパッチ"></a>

### プログラムによるディスパッチ

javascriptまたはフロントエンドコンポーネント内から`d-wire`イベントを送出します。

```javascript
Socket.emit('dashboard:refresh', {}, '#stats-panel');
this.wire('notification:dismiss', { id: this.notificationId });
```

<a name="d-liveステート駆動リアクティビティ"></a>

## d-liveステート駆動リアクティビティ

`d-live`はDOM要素をデータベーステーブルに購読させます。モデルの書き込みがそのテーブルに及ぶとフレームワークはアクティブな購読を評価し、一致するクライアントに通知して要素が自身のコンテンツを自動的に再取得して置き換えます。バックエンドハンドラーは不要です。

```html
<div d-live="posts">
  @foreach(const post of await Post.where({ status: 'published' }).orderBy('created_at', 'DESC').get())
    <article>
      <h2>{{ post.title }}</h2>
      <p>{{ post.excerpt }}</p>
    </article>
  @endforeach
</div>
```

単一ページ上で複数の要素が同一または異なるテーブルを同時に購読できます。

<a name="フィルタリング"></a>

### フィルタリング

`d-live-filter`は更新対象を特定の条件に一致する行に制限します。サーバーはクライアントに通知する前に変更された行に対してフィルターを評価します。フィルターに一致しないクライアントにはメッセージが送信されず再取得も行われません。

```html
<div d-live="orders" d-live-filter="user_id:{{ user.id }}"></div>
```

サポートされている演算子は以下のとおりです。

| 演算子 | 例 | 意味 |
| ------------- | ------------------- | --------------------- |
| `=`（デフォルト） | `status:published` | 一致 |
| `!=` | `status:!=archived` | 不一致 |
| `>` | `price:>100` | より大きい |
| `<` | `count:<5` | 未満 |
| `>=` | `rating:>=4` | 以上 |
| `<=` | `stock:<=10` | 以下 |

複数のフィルターはANDロジックを使用します。区切りにはカンマを使用します。

```html
<div d-live="messages" d-live-filter="room_id:{{ room.id }},status:visible"></div>
```

<a name="動作の仕組み"></a>

### 動作の仕組み

1. マウント時に対象要素はソケット経由で購読メッセージを送信し、フィルター条件とともにそのテーブルに自身を登録します。
2. クエリビルダーが書き込みを実行するとテーブル名と変更データをソケットルーターに通知します。
3. ルーターはアクティブな購読を走査し変更データに対して各フィルターを評価し、フィルターが一致したクライアントにのみ通知を送信します。
4. 購読要素は自身のコンテンツを再レンダリングします。一括操作を効率的に処理するため更新は100ミリ秒にデバウンスされます。二重取得を防ぐためフォーム送信の成功後250ミリ秒間は更新が抑制されます。

<a name="局所的ステート同期"></a>

## 局所的ステート同期

テンプレートを再レンダリングすることなくコンポーネントのリアクティブメモリにステートを直接プッシュします。これは完全なHTML置換を必要としない軽量なステート更新に役立ちます。

```javascript
Socket.setState('#notification-badge', { unread: 14 });
```

対象コンポーネントは自動的に自身のsetStateメソッドを呼び出し、renderおよびeffectループをトリガーします。

<a name="エラーハンドリング"></a>

## エラーハンドリング

SPAとリアクティビティはabortヘルパーと統合されています。

フォーム送信は標準のfetchリクエストを使用します。abortメソッドを呼び出すと構造化されたJSONエラーオブジェクトが返され、フォームは関連する入力欄の直下にインラインでレンダリングします。

SPAナビゲーションはバックグラウンドリクエストを使用します。abortメソッドを呼び出すと完全なエラーページのHTMLがレンダリングされ、SPAレイヤーがそれを表示してURLに反映します。またソケットルーティングハンドラーはレンダリング時の例外を正常にキャッチしてログに記録し、必要に応じてクライアントに安全なエラーメッセージへとフォールバックします。
