<a name="はじめに"></a>

## はじめに

webpackやviteのような外部ツールに依存する従来のフレームワークとは異なり、dframeworkには独自の高度に特化した設定不要のビルドパイプラインとフロントエンドランタイムが含まれています。ビルドパイプラインは未使用のCSSを削除し、クラス名を難読化し、ビューやルートを高速な内部表現にコンパイルします。同時に、フロントエンドのクライアントランタイム（`dstrn.js`）はブラウザー内で透過的な最適化を実行し、ネットワーク使用を合理化し、画面外リソースをスロットリングし、メモリリークを防止します。

<a name="ビルドパイプライン"></a>

## ビルドパイプライン

パイプラインはアプリケーションが`production`環境で起動したときに自動的に実行されます。`views`ディレクトリと`routes`ディレクトリのフィンガープリントを計算します。前回のビルド以降フィンガープリントに変更がない場合（`storage/framework/pipeline.json`で追跡）、パイプラインはキャッシュされた生成物を即座に読み込み、起動時間を数ミリ秒に短縮します。

変更が検出された場合、パイプラインは3つの主要フェーズ（ビューコンパイル、CSS最適化、ルートコンパイル）を実行します。

<a name="ビューのコンパイル"></a>

## ビューのコンパイル

第1フェーズではすべての`.d`ビューテンプレートを生のjavascript関数（`.dc`ファイル）にコンパイルします。これらのコンパイル済みファイルは`storage/framework/views`に保存されます。

> [!NOTE]
> コンパイルされた`.dc`ビューは`manifest.json`内の暗号論的HMACで署名されます。実行時にフレームワークはこれらの署名を検証し、コンパイル済みビューが改ざんされていないことを保証します。

<a name="cssの最適化と難読化"></a>

## cssの最適化と難読化

ビューのコンパイルが完了すると、パイプラインは`.dc`ファイルと公開javascriptファイルをスキャンしてプロジェクト内で使用されているすべてのCSSクラス名を抽出します。

その後CSSオプティマイザーはフレームワークのユーティリティCSSを以下のステップで処理します:

1. **ツリーシェイキング**: ビューやjavascript内で見つからないユーティリティクラスは完全に削除されます。
2. **難読化**: 保持されたすべてのユーティリティクラスは短くランダムな文字列シーケンスに名前が変更されます（例: `mt-4`は`ab`になります）。
3. **書き換え**: オプティマイザーはコンパイル済みの`.dc`ビューおよび公開javascriptファイルを直接編集し、元のクラス名を難読化されたクラス名に置き換えます。
4. **整合性更新**: 変更された`.dc`ファイルの新しい暗号署名によって`manifest.json`が自動更新されます。
5. **最小化**: 基本CSS、難読化されたユーティリティ、アイコン、コンポーネント、およびカスタムCSSがバンドルされ`storage/framework/public/css/dstrn.css`に最小化されます。

オプティマイザーは標準の`class=""`属性、`:class`、`x-bind:class`、`v-bind:class`などの動的バインディング、およびjavascriptの`classList`操作内のクラスを正常に識別して書き換えます。

デバッグ目的で元のクラス名と難読化されたクラス名の対応関係をマッピングした`css-map.json`ファイルが`storage/framework`ディレクトリに書き出されます。

### 動的クラスのセーフリスト登録

OPTIMIZE_CSSまたはcss.optimizeがtrueの場合、ユーティリティクラスは`.d`ビューおよび公開javascript内の静的な使用状況に基づいてツリーシェイクおよび難読化されます。クラスを動的に構築したり実行時に生成したりする場合は、バンドル内で保持され難読化されないようにセーフリストに登録できます:

`config/app.js`の`css.safelist`配列に正確なクラス名、末尾が`*`のワイルドカード文字列、または正規表現を指定します:

```javascript
export default {
  css: {
    optimize: Env.value('OPTIMIZE_CSS', true),
    safelist: ['card', 'badge-*', /^nav-/],
  },
};
```

- 完全一致トークン（例: `card`）は`.card`とそのレスポンシブバリアント（例: `md:card`）のみを保持し、`card-header`のような複合ユーティリティには一致しません。
- ワイルドカードトークン（例: `badge-*`）は一致するすべてのユーティリティクラスとそのレスポンシブバリアント（例: `md:badge-pill`）を保持します。
- ビューやクライアントスクリプト内の動的プレフィックスを持つテンプレートリテラル（例: ``btn-${size}``）は手動設定なしで自動的に検出され保持されます。

### css最適化のオプトアウト

CSSの最小化、ツリーシェイキング、難読化を完全にスキップしたい場合は、`config/app.js`の設定を更新してオプトアウトできます。

```javascript
export default {
  css: {
    optimize: Env.value('OPTIMIZE_CSS', true),
  },
};
```

最適化が無効になっている場合でもパイプラインはコアCSSとユーザーCSSファイルを単一の`dstrn.css`ペイロードに結合しますが、クラス名の難読化や書き換えは行いません。

<a name="ルートのコンパイル"></a>

## ルートのコンパイル

最後に`RouteCompiler`がルート定義と対応するコントローラーハンドラーをスキャンします。ソースコードを解析して各ルートに必要なミドルウェア、依存関係、ペイロードタイプを正確に特定します。

このデータは高度に最適化されたルートキャッシュ（`storage/framework/routes`）にコンパイルされ、受信HTTPリクエストに対する実行時のリフレクションや依存関係の解決を完全にスキップします。

<a name="ランタイムパフォーマンスの最適化"></a>

## ランタイムパフォーマンスの最適化

ビルド時の最適化に加えて、`dstrn.js`のフレームワークランタイムはブラウザー内で複数のパフォーマンス最適化を透過的に適用します。これらの最適化は手動設定や開発者の介入を必要とせず自動的に実行されます。

<a name="画面外リソースのスロットリング"></a>

### 画面外リソースのスロットリング

ランタイムは120pxのバッファを持つインターセクションオブザーバーを初期化し、主要なレイアウトセクション（`header`、`section`、`article`、`main`、`footer`、`aside`、`.section-frame`、`[d-section]`、`[data-section]`）、SVGアニメーション（`animate`、`animateMotion`、`animateTransform`）、および`d-pause-offscreen`が付与された要素を監視します。

監視対象の要素がビューポート外に移動したとき:

1. 要素に`d-paused`属性が付与されます。
2. 要素上で`d-pause`カスタムイベントが送出されます。
3. 要素内のアクティブなSVGアニメーションが`pauseAnimations()`によって一時停止されます。
4. 再生中のHTML5 `<video>`または`<audio>`要素が一時停止され、自動再開の対象としてマークされます。

要素がビューポートに再び入ったとき:

1. `d-paused`属性が削除されます。
2. 要素上で`d-resume`カスタムイベントが送出されます。
3. SVGアニメーションが`unpauseAnimations()`によって自動的に再開されます。
4. オプティマイザーによって一時停止されていたメディア要素の再生が自動的に再開されます。

`<canvas>`または`<d-drawer>`要素を含む要素は画面外スロットリングから自動的に除外されます。また`d-no-optimize`属性を追加することで任意の要素またはサブツリーをオプトアウトできます。

<a name="透過的なcsrf管理"></a>

### 透過的なcsrf管理

ランタイムは同一オリジンの変更系HTTPリクエスト（`POST`、`PUT`、`PATCH`、`DELETE`）をインターセプトするために`window.fetch`をラップします。リクエストに`X-CSRF-TOKEN`ヘッダーがまだ含まれていない場合、ランタイムはドキュメントhead内の`<meta name="csrf-token">`タグからトークンを抽出し自動的に添付します。

シングルページアプリケーションのナビゲーション時、ランタイムはサーバーレスポンスから最新の`csrf-token`および`shield-challenge`メタタグを抽出し手動のステート管理なしで現在のドキュメントheadと同期します。

<a name="二重送信のロック"></a>

### 二重送信のロック

`<d-form>`を利用したフォームは偶発的な重複送信や競合状態を自動的に防止します。submitイベントの送出時にフォームは内部的な送信ロックを設定しネストされたすべてのインタラクティブコントロール（`input`、`textarea`、`select`、`button`）を無効化します。

コントロールはバリデーションおよびネットワーク転送の間無効化されたままとなり、レスポンスが処理されるかバリデーションエラーが表示された後にのみ再度有効化されます。

<a name="ナビゲーションのファストパスとリクエストのキャンセル"></a>

### ナビゲーションのファストパスとリクエストのキャンセル

ナビゲーションランタイムはシングルページアプリケーションの遷移中におけるネットワークアクティビティを最適化します:

1. **リクエストの重複排除**: 同じ遷移先URLへの同時ナビゲーションリクエストは重複したネットワークリクエストを発行するのではなく実行中のアクティブなプロミスを再利用します。
2. **リクエストのキャンセル**: 新しいナビゲーションを開始すると`AbortController`を使用して先行する処理中のナビゲーションフェッチが自動的に中止され、古いレスポンスが新しいページコンテンツを上書きするのを防ぎます。
3. **同一ページハッシュのファストパス**: 現在のページ上のハッシュを指すアンカー（例: `/`にいるときの`/#features`）をクリックするとネットワークフェッチを完全にスキップし対象要素をビューまでスクロールしてブラウザー履歴を同期します。

<a name="domモーフィングとペイロードハッシュ化"></a>

### domモーフィングとペイロードハッシュ化

ページコンテンツの更新時、ランタイムはインプレースDOMモーフィングアルゴリズムを使用することで破壊的な内部HTML置換を回避します。モーフィング処理は変更された属性、テキストノード、フォームコントロール状態（`input`、`textarea`、`select`、`option`）のみを更新し、アクティブ要素のフォーカス、テキスト選択、スクロール位置を保持します。

リアルタイムのリアクティブ更新向け:

1. **ペイロードのハッシュ化**: 受信した`d-wire:render`更新はレンダリングされたHTML文字列の32ビットハッシュ（`__wire_last_hash`）を計算します。ペイロードが現在のハッシュと一致する場合、DOMモーフィングは完全にスキップされます。
2. **局所更新のデバウンス**: 冗長な再フェッチを防ぐため`d-live`モデルの更新は100ミリ秒デバウンスされ、フォーム送信の成功後250ミリ秒間は抑制されます。

<a name="自動スコープライフサイクルとクリーンアップ"></a>

### 自動スコープライフサイクルとクリーンアップ

差し替えられた各ビューコンテナーは分離されたライフサイクル認識スコープ内でスクリプトを実行します。常駐する`MutationObserver`が要素の削除をドキュメントツリーで監視します。

コンテナー要素がDOMから削除されると、そのスコープは自動的に破棄されます。ランタイムはすべてのアクティブなタイムアウト（`clearTimeout`）、インターバル（`clearInterval`）、アニメーションフレーム（`cancelAnimationFrame`）をクリアし、`AbortController`を通じて保留中のスコープ付き`fetch`リクエストを中止し、アタッチされたすべてのイベントリスナーとソケット購読を解除します。

ローカル開発環境ではランタイムがナビゲーションをまたいだスコープの存続を監視し、有効なDOMノードに紐づかない孤立したスコープが存続している場合に警告を発します。

<a name="誤操作によるナビゲーション防止ガード"></a>

### 誤操作によるナビゲーション防止ガード

ランタイムはBackspaceキーのグローバルキーボードハンドラーを登録します。編集可能なフォームコントロール（テキスト入力、textarea、または`isContentEditable`要素など）にフォーカスがない状態でユーザーがBackspaceキーを押した場合、意図しないデータ損失を防ぐためブラウザーのデフォルトの履歴バックナビゲーションが防止されます。
