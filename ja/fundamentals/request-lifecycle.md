<a name="はじめに"></a>

## はじめに

リクエストがdframework内をどのように流れるかを理解することは、予測可能なアプリケーションを構築する上で極めて重要です。フレームワークは閉ループとして動作します。受信するすべてのhttpリクエストはフレームワークエンジンによって内部的にインターセプト、パース、ルーティングされます。開発中に基本的なリクエスト処理のために外部Webサーバーを設定する必要はありません。

<a name="単一アプリケーションインスタンス"></a>

## 単一アプリケーションインスタンス

dframeworkはnodeプロセスごとに単一のアプリケーションインスタンスを強制します。アプリケーションコンテナは設定、ストレージディスク、データベース接続プール、ロガーを含むプロセスレベルのシングルトンを管理します。

同一プロセス内で複数のアプリケーションインスタンスを同時にインスタンス化しようとするとエラーがスローされます。

<a name="ライフサイクルの概要"></a>

## ライフサイクルの概要

リクエストがアプリケーションに入ると、まず中央のアプリケーションハンドラーに到達します。フレームワークはアプリケーションがキャッシュ有効な本番環境で実行されているかどうかを即座に判定します。

<a name="高速パス"></a>

### 高速パス

高速パスがアクティブな場合、リクエストはいくつかの初期化ステップをバイパスし、コンパイル済みの`.rc`ファイルに格納されている事前コンパイルされたルーティングテーブルへ直接ジャンプします。この積極的な最適化により、静的ルートとキャッシュされたレスポンスのレイテンシが大幅に削減されます。フレームワークは本番環境での実行時、手動のビルドステップを必要とせずにアプリケーション起動時にこれらの高度に最適化されたファイルを自動生成します。

```javascript
// internal framework code demonstrating the fast path execution
if (matchedStatic && matchedStatic._compiled) {
  request.params = {};
  
  // instantly execute the compiled .rc handler
  const result = RequestContext.run(request, () =>
    matchedStatic._compiled(request, response, this, this.router)
  );
  return this.settleRoute(result, request, response);
}
```

<a name="リクエストパイプライン"></a>

### リクエストパイプライン

高速パスが適用されない場合、リクエストはリクエストパイプラインに入ります。パイプラインはアプリケーションロジックに到達する前に内部ステージに対してリクエストを評価する専用コンポーネントです。
まずリクエストがデバッグバーやshieldセキュリティスクリプトなどの内部アセットを要求しているかチェックします。一致が見つかった場合、パイプラインはメモリからアセットを直接配信します。

<a name="静的ファイルとアセット"></a>

### 静的ファイルとアセット

次にパイプラインは静的ファイルを評価します。静的ファイルの配信が有効な場合、パイプラインは`public`ディレクトリをチェックします。有効なファイルが存在する場合、適切なキャッシングヘッダーを付与してクライアントにファイルをストリーミングします。リクエストがいずれの静的ファイルにも一致しない場合、パイプラインはアプリケーションルーターに制御を引き渡します。

> [!NOTE]
> ローカル開発中、内部サーバーは完全に機能する静的ファイルサーバーとして動作します。本番環境では静的アセットの処理をnginxまたはcdnに任せることを推奨します。

<a name="ルーティングとミドルウェア"></a>

### ルーティングとミドルウェア

ルーターは中核となる意思決定エンジンです。生のリクエストを受け取り、管理されたリクエストコンテキストでラップして、定義されたルートに対してurlを照合します。

ルートが一致すると、ルーターはミドルウェアの処理を開始します。ミドルウェアはリクエストが通過しなければならない実行チェーンを形成します。いずれかのミドルウェアがアボートするかレスポンスを返した場合、チェーンは即座に停止しレスポンスがクライアントへ返送されます。

<a name="コントローラーへのディスパッチ"></a>

### コントローラーへのディスパッチ

最後にすべてのミドルウェアを通過した場合、リクエストは指定されたコントローラーに到達します。フレームワークにおけるコントローラーは非同期メソッドを定義するシンプルなクラスです。リクエストやレスポンスなどの引数は任意であり、ビジネスロジックを極めてクリーンに保つことができます。結果は管理されたレスポンスオブジェクトに変換され、最終的にクライアントへフラッシュされてライフサイクルが完了します。

```javascript
// controllers/UserController.js
export default class UserController {
  async show(req) {
    const user = await User.find(req.params.id);
    
    // the json response is flushed directly back to the client
    return json({ user });
  }
}
```
