## v0.21.0

v0.21.0はdframeworkの統合プロダクションリリースであり、完全なクローズドワールドアーキテクチャ、ネイティブトランスポートアドオン、コンパイル済みテンプレートエンジン、dspaクライアントルーター、クロスプラットフォームネイティブランタイムを統合したバージョンです。

<a name="コアランタイムとトランスポート"></a>

### コアランタイムとトランスポート

- libuvイベントループ統合と最適化されたTCP処理によってコンパイルされた高性能カスタムネイティブトランスポートアドオン（`dfws`）
- ターゲットプラットフォームでネイティブバイナリが利用できない場合にNode標準の組み込みHTTPサーバーへ自動的かつ静かにフォールバック
- 設定の検出、ロギング、ルーター初期化、リクエストディスパッチを管理する一元的なアプリケーション起動ライフサイクル
- グローバルスコープに割り当てられた明示的なレスポンスヘルパー（`return json()`、`return render()`、`return redirect()`、`return back()`、`return abort()`、`return status()`）
- ヘッダー、クッキー、クエリパラメータ、マルチパートファイルアップロード、JSONペイロードをサポートするリクエストコンテキスト抽象化

<a name="宣言的ルーティングとミドルウェア"></a>

### 宣言的ルーティングとミドルウェア

- 流暢な宣言的ルーティングファサード（`Route.get()`、`Route.post()`、`Route.put()`、`Route.delete()`）
- パスプレフィックス、名前付きルートプレフィックス、共有ミドルウェアパイプラインをサポートするルートグループスコープ
- 低オーバーヘッドなルートディスパッチを実現するコンパイル済み正規表現ルートマッチングエンジン
- ルート実行前および実行後ハンドラーを実行するパイプラインベースのミドルウェアランナー
- 一元的なエラーハンドリングとカスタムエラーテンプレートレンダリング（`404.d`、`500.d`、`debug.d`）

<a name="データベースとActive Record"></a>

### データベースとActive Record

- 自動再接続と非同期クエリ実行を備えたデータベース接続プーリング
- 流暢なクエリ構築を備えたActive Recordモデル基底クラス（`where()`、`find()`、`create()`、`update()`、`delete()`、`first()`、`paginate()`）
- `hasOne`、`hasMany`、`belongsTo`、`belongsToMany`をサポートするデータベースリレーション
- 流暢なスキーマ定義とマイグレーションエンジン（`dstrn migrate`、`dstrn migrate:rollback`、`dstrn migrate:status`）
- データベースシーダーランナー（`dstrn seed`、`dstrn seed:make`）
- すべての内部クエリでのパラメータバインディングの強制適用

<a name="ビューエンジンとコンパイラ"></a>

### ビューエンジンとコンパイラ

- テンプレートファイルをキャッシュされたJavaScriptモジュールへ直接コンパイルするコンパイル済み`.d`テンプレートエンジン
- `@extends`、`@section`、`@yield`によるテンプレート継承
- `@include`およびコンポーネントスロットによる再利用可能なパーシャル
- 組み込みテンプレートディレクティブ: `@if`、`@elseif`、`@else`、`@foreach`、`@for`、`@forelse`、`@ruby`、`@t`、`@js`、`@json`
- 同一ファイル内でのビューデータ計算を可能にするサーバーサイドJavaScript実行ブロック（`@js`から`@endjs`）
- すべてのHTMLフォーム出力に対するCSRFトークンの自動注入

<a name="フロントエンドパイプラインとdspaルーター"></a>

### フロントエンドパイプラインとdspaルーター

- pushState履歴管理を伴い`<d-link>`ナビゲーションと`<d-form>`送信をインターセプトする軽量クライアントサイドSPAルーター
- `d-wire`による宣言的DOMイベントバインディングと`d-live`によるリアルタイム更新バインディング
- 組み込みカスタムUI要素（`d-hold-button`、`d-modal`、`d-drawer`、`d-dropdown`、`d-combobox`、`d-file-input`、`d-color-picker`、`d-toggle`、`d-slider`、`d-skeleton`、`d-context-menu`）
- 3段階のエレベーション（`bg-container-d`、`bg-container`、`bg-container-l`）、コントラスト階層、レスポンシブブレークポイントプレフィックスを備えたユーティリティクラススタイリングシステム（`dstrn.css`）
- ビルド時アセット圧縮およびバンドルパイプライン

<a name="セキュリティとセッション"></a>

### セキュリティとセッション

- 自動CSRFトークン生成、クッキー署名、PoW検証を提供するShieldガードミドルウェア
- IPベースのスライディングウィンドウとレスポンスヘッダーによる設定可能なレートリミット
- bcryptパスワードハッシュファサード（`Hash.make()`、`Hash.verify()`）
- セッションドライバー: メモリセッションドライバー、分散状態向けデータベースセッションドライバー、暗号化クライアント状態向けステルスセッションドライバー
- 入力バリデーションエンジン

<a name="キューとタスクスケジューラ"></a>

### キューとタスクスケジューラ

- 設定可能な並行性およびワーカー制限を備えたワーカースレッドバックグラウンドキューシステム
- シリアライズされたペイロード受け渡しを行うジョブディスパッチファサード（`Job.dispatch()`）
- 定期実行コマンドやメンテナンスタスクを実行するタスクスケジューラ（`console/Schedule.js`）

<a name="ネイティブブリッジとプラットフォームランタイム"></a>

### ネイティブブリッジとプラットフォームランタイム

- Webとネイティブシェルの両方で統一された`App.native`クライアントAPIを公開するクロスプラットフォームネイティブブリッジ
- 純粋な境界ウィンドウ処理、WebKitビュー、ネイティブブリッジディスパッチを使用してSwiftで構築されたiOSランタイムシェル
- セキュアなWebView構成とブリッジインターフェースを使用してKotlinで構築されたAndroidランタイムシェル
- Tauriと分離されたWebViewセキュリティプロファイルを使用してRustで構築されたデスクトップランタイムシェル
- 自動Webフォールバックを備えた設定不要の4ファイル構成プラグインアーキテクチャ（`index.js`、`Plugin.swift`、`Plugin.kt`、`Plugin.rs`）
- 組み込みコアプラグイン: `auth`（KeychainおよびKeystoreによる保護）、`device`（ハードウェアメタデータ）、`storage`（セキュア永続ストレージ）、`crypto`（ECDSA P256 WebCryptoおよびハードウェアキー生成）、`audio`（ネイティブプレイヤーパイプライン）、`notifications`（システム通知センター）

<a name="CLIとアーキテクチャアナライザー"></a>

### CLIとアーキテクチャアナライザー

- グローバルコマンドラインバイナリ（`dstrn`）
- 視覚的依存関係グラフ生成（`dstrn graph`）、境界ルール強制（`dstrn lint`）、デッドコード検出（`dstrn dead`）、プロジェクト健全性スコアリング（`dstrn doctor`）を備えた静的アーキテクチャアナライザー
- 辞書とビューキーを検証する翻訳パリティ検証（`dstrn lang:lint`）
- 事前ロードされたアプリケーションコンテキストとモデルインスタンスを備えた対話型REPLシェル（`dstrn tinker`）
- ネイティブ開発シミュレータとプロダクションビルダー（`dstrn simulate`、`dstrn build`）
- 自動デプロイと証明書処理（`dstrn deploy`、`dstrn cert`）

<a name="開発の歴史（2019年から2026年）"></a>

## 開発の歴史（2019年から2026年）

dframeworkはツールチェーンの断片化を排除しフロントエンドとバックエンドの全システムにわたって一貫性を強制するために2019年に開発が開始されました。2019年から2026年の間に、フレームワークは0.21バージョンに至るまで複数の基盤的イテレーションを経て進化しました。

<a name="開発マイルストーン（v0.1.0からv0.20.0）"></a>

### 開発マイルストーン（v0.1.0からv0.20.0）

- **2019年から2020年（スタイリング基盤とクライアントヘルパー）:** フレームワークはクライアントサイドのスタイリングシステムおよびユーティリティ層として始まりました。JavaScriptヘルパー、基本ユーティリティCSS定義（後に`dstrn.css`を形成）、最初期のカスタムフロントエンドUIコンポーネントが含まれていました。このバージョンはdstrn.xyzの最初のリリース構築に使用されました。
- **2020年から2021年（フロントエンドランタイムとバックエンドの初期探索）:** コアフロントエンドコンポーネントが洗練され、クライアントサイドシングルページアプリケーションランタイムの初期イテレーションが作成されました。コアバックエンド機能（Active Recordモデル、データベース抽象化、バックグラウンドキュー、ネイティブモバイルスタブ）に関する初期の探索的開発が始まりました。
- **2021年から2022年（SPAの安定化とドキュメントデータベースのイテレーション）:** SPAランタイムはpushState履歴ナビゲーションとDOMスワッピングにより安定した状態に達しました。ドキュメントデータベース（MongoDB）向けのアダプター層が実装されました。スタイリングシステムは厳格なエレベーションとコントラスト規則によって洗練されました。このイテレーションはdstrn.xyzのクローズドリリースの基盤となりました。
- **2022年から2023年（フルフレームワークへの移行とCLIランタイム）:** 活発な開発は統一されたフルスタックフレームワークの構築へと移行しました。`dstrn` CLI、スキャフォールディングツール、開発ランタイムの最初のバージョンが作成されました。初期のルーティングメカニズムが導入されましたが、バックエンドのスループットとリクエストディスパッチは従来の高性能スタックに対して依然として競争力が不足していました。
- **2023年から2024年（フロントエンドの最適化、標準化、リアクティビティ）:** 集中的なパフォーマンスチューニングによりフロントエンドのレンダリングレイテンシとDOMミューテーション時間が最小限に抑えられました。クライアントランタイムAPIが標準化され、宣言的リアクティビティバインディング（`d-wire`および`d-live`）が導入され、包括的なフロントエンドドキュメントが作成されました。
- **2024年から2025年（データベースドライバー、ビューコンパイラ、トランスポートの研究）:** フレームワークアーキテクチャが現在の構造へと合致しました。ルーターはディスパッチオーバーヘッドを削減するためにコンパイル済み正規表現で再設計され、`.d`テンプレートコンパイラが構築されました。MongoDBはスキーマの柔軟性に関する制約から完全に削除され、パラメータバインディングとマイグレーションを備えたデータベースドライバー抽象化およびActive Record ORM層に置き換えられました。標準のNode HTTPサーバーでは制約が大きすぎたため、カスタムネイティブトランスポートアドオン（`dfws`）の研究と初期実装が開始されました。
- **2025年から2026年（トランスポートベンチマークとマイクロ最適化）:** 競合フレームワークに対する徹底的な負荷テストとベンチマークが実施されました。すべての層、Active Recordのクエリバッチ処理、シリアライゼーションパイプラインにわたって的確なマイクロ最適化が適用され、スループットの面で極めて高い競争力を獲得しました。データベース層、Active Record ORM、ワーカーキュー、スケジューラ、設定不要のネイティブプラットフォームプラグイン（iOS Swift、Android Kotlin、デスクトップRust）が機能的に完成しました。
- **2026年以降（プロダクション強化とリリース0.21）:** すべてのサブシステムが磨き上げられ、厳密に最適化され、クローズドワールドアーキテクチャへと統合され、v0.21.0のプロダクション基準が確立されました。
