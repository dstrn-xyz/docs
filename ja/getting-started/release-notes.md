<a name="バージョニングスキーム"></a>

## バージョニングスキーム

dframeworkはすべてのサブシステム間で一貫性を維持するように設計された構造化バージョニングスキームを採用しています。

<a name="バージョン構造"></a>

### バージョン構造

バージョン番号は標準的な3セグメント形式に従います:

```
major.minor.patch
```

1.0以前のシリーズ（0.xリリース）ではフレームワークはマイナーインクリメントを主要なアーキテクチャ境界として扱います:

- `0.X.0`（マイナーインクリメント）: メジャーリリースとして機能します。主要な新機能やアーキテクチャの刷新を導入し、破壊的変更を含む場合があります。
- `0.X.Y`（パッチインクリメント）: メンテナンス、バグ修正、パフォーマンス最適化、非破壊的な改良を表します。

1.0マイルストーン以降はメジャーバージョンの引き上げのみに破壊的変更が含まれる標準的なセマンティックバージョニングが適用されます。

<a name="メジャーバージョン"></a>

### メジャーバージョン

メジャーバージョンは実質的な改善やコア機能の追加が導入された際にリリースされます。

dframeworkはルーティング、テンプレート、スタイリング、データベース管理、ネイティブコンパイルが一体となって動作するクローズドワールドアーキテクチャを維持しているため、メジャーバージョンはプラットフォーム全体を同時に進化させます。

> [!IMPORTANT]
> メジャーリリースにはフレームワークAPI、設定構造、コンパイラ動作に対する破壊的変更が含まれる場合があります。すべての破壊的変更は直接の移行手順とともにリリース変更履歴に記載されます。

<a name="マイナーおよびパッチバージョン"></a>

### マイナーおよびパッチバージョン

マイナーおよびパッチバージョンに破壊的変更が含まれることはありません。同一リリースシリーズ内では厳格な下位互換性が維持されます。

パッチリリースは以下の点に焦点を当てています:
- コアサブシステムのバグ修正
- パフォーマンスおよびメモリの最適化
- コンパイラおよびビルドパイプラインの強化
- ネイティブブリッジの信頼性修正
- セキュリティ強化および依存関係のメンテナンス

アプリケーションコードやデータベーススキーマを変更することなく、新しいパッチバージョンへ安全にアップデートできます。

<a name="サポートポリシー"></a>

## サポートポリシー

dframeworkは開発リソースの集中を保つために最新リリースシリーズに焦点を当てたサポートを提供します。

| バージョンシリーズ | ステータス | バグ修正 | セキュリティ修正 |
| --- | --- | --- | --- |
| 0.21.x（現行） | アクティブ | サポート対象 | サポート対象 |
| 0.20.x以前 | サポート終了 | なし | なし |

<a name="アクティブサポート"></a>

### アクティブサポート

アクティブサポートは最新のリリースシリーズに対してのみ提供されます。すべてのバグ修正、機能改善、パフォーマンス向上はアクティブブランチに直接適用され、パッチリリースとして公開されます。

以前のリリースシリーズにはバグ修正のバックポートは行われません。以前のバージョンで問題が発生した場合の標準的な解決策は最新リリースへのアップグレードです。

<a name="セキュリティ修正"></a>

### セキュリティ修正

セキュリティ脆弱性は最優先で調査および解決されます。アクティブなリリースシリーズに対してセキュリティパッチが即座に公開されます。

重大な脆弱性が特定された場合、パッチリリースが公開されユーザーへデプロイの更新が推奨されます。

<a name="前方進化"></a>

### 前方進化

dframeworkは厳格な前方進化の理念に従っています。レガシー互換シムや非推奨のアダプター層はランタイムオーバーヘッドを生み出し内部コードパスを複雑化させるため意図的に排除されています。

アーキテクチャの規約が改良された場合、アプリケーションは新しいパターンへと前方移行することが前提とされます。

<a name="安定性の保証"></a>

## 安定性の保証

<a name="統合パッケージの一貫性"></a>

### 統合パッケージの一貫性

dframeworkは単一の完全に統合されたパッケージとして提供されます。すべてのフレームワークコンポーネント（サーバーランタイム、Active Record ORM、コンパイル済みビューエンジン、クライアントスタイリングシステム、dspaルーター、ワーカーキュー、スケジューラ、CLIツール、ネイティブブリッジを含む）は同時にバージョニングされリリースされます。

<a name="クロスプラットフォームランタイムパリティ"></a>

### クロスプラットフォームランタイムパリティ

ネイティブシェルランタイム（iOS Swift、Android Kotlin、デスクトップTauri Rust）はフレームワークパッケージに直接統合されています。ネイティブブリッジプロトコルとJavaScript参照実装はリリースごとにサポート対象のすべてのプラットフォームに対してテストおよび検証されます。

<a name="アプリケーションのアップグレード"></a>

## アプリケーションのアップグレード

<a name="アップグレードパス"></a>

### アップグレードパス

既存のアプリケーションを現在のシリーズ内の最新パッチリリースにアップグレードするには、`package.json`のパッケージバージョンを更新して依存関係を再インストールします:

```bash
npm install dframework@npm:@dstrn/framework@latest
```

更新後、アプリケーションサーバーを再起動してアセットをコンパイルしランタイム動作を確認します:

```bash
dstrn serve
```

<a name="破壊的変更の通知"></a>

### 破壊的変更の通知

メジャーリリース間を移行する場合（0.21から0.22など）、本番システムを更新する前に[変更履歴](changelog.md)を確認して破壊的変更の通知と移行手順を把握してください。
